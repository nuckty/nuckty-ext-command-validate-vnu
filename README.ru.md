# nuckty-ext-command-validate-vnu

> **Проверка собранного HTML через W3C Nu Html Checker — команда `validate`.**

Необязательное командное расширение для [nuckty](https://github.com/nuckty/nuckty). Прогоняет каждый собранный файл `<outDir>/html/` через Nu Html Checker (vnu.jar), который проверяет минимальный HTML с разрешённым стандартом пропуском необязательных тегов.

Расширение требует JVM и подключается по необходимости. Модульные тесты минимизатора проверяют конкретные правила движка; они не проверяют произвольную структуру пользовательских шаблонов.

## Что добавляет

Одну команду CLI, регистрируемую через `env.commands`:

```
nuckty validate [target]
```

Проверяет каждый файл HTML артефакта и сообщает ноль ошибок, когда минимальный вывод корректен.

## Как работает

Расширение запускает одну JVM на время команды и отправляет параллельные запросы HTTP к vnu.jar (не более восьми одновременно). Кэш по содержимому хранится только в памяти этого процесса; новый запуск CLI проверяет файлы заново. Демон запускается при первой проверке и завершается в очистке команды, в том числе при ошибке.

Порт `127.0.0.1:8888` должен быть свободен: уже занятый порт вызывает ошибку до запуска Java. Проверка доступности не исключает захват порта другим процессом между проверкой и запуском Java. Результаты модульных тестов не заменяют проверку произвольных пользовательских шаблонов.

## Требования

- `java` в `PATH` (JVM 17+). Время запуска и проверки зависит от JVM, оборудования и числа файлов.
- `vnu-jar` версии 26.8.20 входит в зависимости расширения; отдельная установка потребителю не нужна.

- Необязательно — в CI не ставится, если проверка не входит в конвейер.

Установите системную JVM до установки расширения. Скрипт установки `vnu-jar` при отсутствии Java пробует скачать собственную JRE; расширение Nuckty вызывает `java` из `PATH`. В CI системная Java проверяется до установки зависимостей валидатора.

Ядро не зависит от vnu и JVM.

## Как подключить

Пример продолжает быстрый старт со стандартным обработчиком `nuckty-ext-block-root`. Добавьте новое расширение в `ext` глобального `config/config-nuckty.ts`, сохранив остальные записи. Если обработчик документа собственный, оставьте его вместо `nuckty-ext-block-root`.

```ts
import { defineNucktyConfig } from 'nuckty';

export default defineNucktyConfig({
    targets: { main: { configDir: 'config/', outDir: 'site/' } },
    ext: ['nuckty-ext-block-root', 'nuckty-ext-command-validate-vnu'],
});
```

Затем:

```bash
npx nuckty build
npx nuckty validate
```

## Контракт

`register(env: NucktyEnv)` добавляет `nuckty validate` через `env.commands.add`. Без имени выбирается первый таргет; команда рекурсивно проверяет `.html` в его `outDir/html`. Пустой набор файлов, ошибки валидации, протокола или завершения демона дают ненулевой код выхода.

## Спецификация

Спецификация `openspec/specs/ext-command-validate-vnu/spec.md` описывает команду проверки, демон HTTP на время одного запуска, параллельную обработку и кэш в памяти. Расширение подключается отдельно и требует JVM.

Интеграционные проверки команд с настоящим рантаймом в PATH запускаются через `NUCKTY_VNU_NATIVE=1 npm test`. В CI этот режим обязателен; иначе сценарий с настоящим процессом явно пропускается.


Если порт по умолчанию занят, используйте `nuckty validate [target] --port 18888`. Допустимо целое число от 1 до 65535; проверка и остановка Java используют выбранный порт.
